# Specification Drafting

## Purpose
Convert analysis findings into a compact first specification draft that can be reviewed and refined.

## When to use
- A first technical specification must be written from analysis notes.
- The workflow needs a draft before contract refinement.

## Inputs
- Domain map
- Flow map
- Risk notes

## Workflow
1. Write scope and boundaries.
2. Define inputs, outputs, and core behavior.
3. Record failure behavior and open assumptions.

## Outputs
- Draft scope
- Draft behavior section
- Draft failure section
- Open assumption list

## Guardrails
- Keep the first draft concise.
- Leave unknowns explicit instead of hiding them.
