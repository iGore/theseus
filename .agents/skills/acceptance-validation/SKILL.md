# Acceptance Validation

## Purpose
Decide whether the current specification or implementation satisfies the stated acceptance criteria.

## When to use
- A review or release gate depends on explicit criteria.
- The team needs a pass/fail view per requirement.

## Inputs
- Acceptance criteria
- Specification and/or implementation evidence

## Workflow
1. Read each criterion as a checkable statement.
2. Match it to evidence.
3. Mark pass, fail, or missing evidence.

## Outputs
- Acceptance checklist
- Evidence links
- Pass/fail summary

## Guardrails
- Do not infer missing evidence.
- Keep validation aligned with the exact criterion wording.
